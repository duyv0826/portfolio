# ADR-001: 采用 Next.js 16 全栈单体架构

## Status
Accepted (2026-10-09)

## Background
洪兄作品集全站为单人维护的 MVP，三大目标（毕业设计展示 / 校园大使 / 求职）均面向中文国内受众。核心约束：

- 百度等国内搜索引擎要求 SSR/ISR 渲染（纯 CSR 抓取差），SEO 是硬需求。
- 域名须解析至大陆服务器并完成 ICP 备案，部署须可备案。
- 仅一名管理员，无多角色 / 多租户需求；MVP 速度优先，避免过度设计。
- 技术栈须与 PRD 的"自己拥有、易更新、合规"定位一致。

备选方案调研见 `architecture.md` §2 对比矩阵：

- 方案 B：Next.js 16 前端 + FastAPI 后端（前后端分离），带来双语言栈、双服务编排、跨域 / CSRF 额外治理成本。
- 方案 C：Nuxt 3 (Vue 3) + Drizzle，Vue 生态替代，但 React 栈在招聘 / 作品集场景认知度更高。

## Decision
采用 **Next.js 16（App Router）全栈单体**：

- 前端页面（SSR / SSG / ISR）+ Route Handlers（`app/api/**/route.ts`）+ Server Actions 同仓同语言（TypeScript）。
- 单一部署单元（Docker Compose 于腾讯云 Lighthouse），无跨服务调用。
- 管理员认证用自建 JWT（access 15min + refresh 7d，httpOnly Cookie），见 ADR-003。
- 数据访问用 Prisma 7（schema-first + 迁移 + 类型安全），见 ADR-005。

## Consequences
- 正面：单仓单语言单部署，运维简单；原生 SSR / ISR 满足百度 SEO；国内部署可备案；Route Handlers 即后端，开发快。
- 负面：无独立后端服务的独立伸缩性（MVP 阶段不需要，可接受）；CMS 与展示同进程，后续若流量大增需拆服务（届时再上 `/api/v1` 微服务化）。
