# ADR-003: 自建 JWT 认证（jose + bcryptjs），否决 Auth.js v5

## Status
Accepted (2026-10-09)

## Background
仅单一管理员，需邮箱 + 密码登录，签发 access(15min) + refresh(7d) 双 httpOnly Cookie，且认证须在 Edge 兼容的中间件中校验（`middleware.ts` 守卫 `/admin`、`/api/admin/*`，未登录返回 401 / 重定向）。

备选 Auth.js v5：调研时点仍带 beta 歧义，且需拆分 Edge / Node 配置；与"精确匹配规范、避免复杂度、无过度设计"目标相悖。自建方案能完全贴合 15min / 7d 的硬性规范。

## Decision
采用 **自建 JWT 认证**：

- `jose@^5` 签发 / 校验（Edge 兼容，Auth.js 内核同款）。
- `bcryptjs@^2.4` 密码哈希（纯 JS，无原生编译，Docker / arm 友好）。
- 双 httpOnly Cookie：`access_token`（15min）+ `refresh_token`（7d）；`POST /api/auth/refresh` 使用 refresh Cookie 静默续期 access。
- 服务端 `AUTH_SECRET` 强随机且绝不入 `NEXT_PUBLIC_*`。

## Consequences
- 正面：完全可控，精确匹配 15min / 7d 规范，无 beta 依赖与 Edge 配置拆分负担。
- 负面：需自写续期轮转与登出（双 Cookie 清除）逻辑；`AUTH_SECRET` 须强随机并服务端保管；中间件须正确处理 access 过期后回落 refresh 续期。
