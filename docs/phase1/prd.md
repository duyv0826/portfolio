## 0. 文档元信息与设计硬约束（不可违反）

以下约束由用户（洪兄）与项目总监确认，作为本 PRD 与后续设计/开发的绝对规则。

| 类别 | 约束内容 |
|------|----------|
| 迭代目标 | 去占位 + 提质（消除 AI 模板味、收敛 magic numbers）+ 统一对外口径 + 真实图片填充 + 加作品详情页 |
| 作品口径 | 《澳里·光景》= 学位作品（互动叙事·Unity）；《青峦·听雨》= 其中可玩叙事子项目，卡片内注明两者关系 |
| 图片来源 | 真实画师授权图（用户后续提供作者 ID + 来源，按小黑盒模式标注）；本轮不填充任何 AI 生成图，图片位预留 artist/source 元数据接口 + 中性占位 |
| 架构 | 零构建纯静态单页（GitHub Pages 托管）；详情页用单页内 hash 路由（#work/<id>）实现，不新增 html、不引框架 |

### P0 绝对规则（违反 = 退回）
1. **禁止 emoji 作功能图标** — PRD 及后续设计中，图标一律用语义词描述（如「外链图标」「箭头图标」「编辑图标」），不使用 🚀/📊 等字符。
2. **禁止紫粉渐变主视觉** — 主色方向为深墨/中性灰 + 单一强调色（建议：青绿或琥珀），不得出现 purple→pink 渐变。
3. **禁止空洞占位文案** — 全站文案为真实中文陈述。禁用词清单：`Welcome to` / `Lorem ipsum` / `Sign up today` / 任意未替换的模板默认句。

## 1. 问题陈述（Problem Statement）

**谁**：洪兄，澳门科技大学 人文艺术学院 互动媒体艺术·游戏设计方向 研究生；其作品集面向（1）求职/实习的招聘方，（2）申请深造的招生委员会，（3）小黑盒/知乎的内容读者与潜在合作方。

**在什么场景下遇到什么痛点**：
- 现有线上作品集站点处于「AI 模板生成后未深度打磨」状态，访客（招聘方/导师）打开后看到的是占位文案、疑似 AI 验证图、空白图片位与前后口径不一致的备注，无法判断真实能力与作品定位。
- 招聘方/导师平均在 3 秒内决定是否继续浏览（行业数据：移动端加载超 3 秒 53% 访客流失；图片型作品集移动端跳出率 57%）。当前站点的占位与空白元素直接拉低首屏可信度。
- 没有作品详情页，访客无法看到《澳里·光景》的设计过程、角色贡献与《青峦·听雨》的「可玩」属性，错失差异化展示机会。

**现在怎么解决的**：依赖一个由模板/AI 生成的静态站点，gallery 区块还引用了已废弃的 COS 脚本。

**为什么不行**：占位与模板味让「真实能力」被淹没；图片全空与失效脚本让站点像未完成品；口径不一致让学位作品与子项目关系模糊，削弱学术叙事的严谨性。这正是同类作品集最被诟病的「停在模板层（Stopping at the template）」问题（来源：Emergent《10 Portfolio Website Mistakes》对 30 个作品集的复盘）。

## 2. 目标用户与用户画像

### 主要用户画像 A：招聘方 / 实习负责人（游戏 / 互动媒体行业）
- 年龄：28–45 岁
- 职业：工作室 recruiter、主美/主策划、HR
- 场景：在手机或 Slack 里点开链接，30 秒内判断是否进入面试；多数不看完整游戏，只看缩略图 + 短视频 + README 式说明
- 技术水平：中。关注「能否做出来」「角色贡献是否清晰」「有没有可玩 demo」
- 核心诉求：**快速判断能力真实性与专业方向**，讨厌慢加载、空图、模板腔

### 主要用户画像 B：招生委员会 / 学术导师（数字媒体艺术 / 叙事设计方向）
- 年龄：35–55 岁
- 职业：MFA / MDes 项目教授、 admissions
- 场景：审阅申请材料时打开作品集，关注设计研究与学术深度
- 技术水平：中高
- 核心诉求：**看到设计思维、研究方法论、作品与学位脉络的关系**，讨厌「只有成品截图没有过程」

### 次要用户画像 C：小黑盒 / 知乎读者与潜在合作方
- 年龄：18–35 岁
- 职业：玩家、独立开发者、内容合作方
- 场景：从小黑盒/知乎文章跳转而来，想看背后作品与真人
- 核心诉求：**内容矩阵互通、能玩到真实作品、能联系到作者**

### 4.3 行业差评与痛点归纳（洪兄可差异化的市场空白）
1. **「停在模板层」**：同模板同文案，访客无法区分作者（Emergent 复盘 30 站）。→ 洪兄用统一设计语言 + 真实文案破局。
2. **首屏前塞满动画/介绍**：招聘方在作品加载前就关标签页。→ 洪兄首屏即作品网格。
3. **只有成品截图没有故事**：缺 problem/role/outcome。→ 洪兄详情页含设计过程与角色贡献。
4. **移动端崩坏**：对比表溢出、未测真机。→ 洪兄移动优先 + 真机验收。
5. **慢加载 / 断链 / 空图**：图片型作品集移动端跳出率 57%。→ 洪兄零构建静态 + 懒加载 + 中性占位 + 去 COS 依赖。
6. **可玩作品缺失**：多数仅截图/视频，极少真实可玩。→ 洪兄以《抉择的房间》等真实网页游戏外链形成最强差异化。
7. **口径/定位混乱**：学位作品与子项目关系不清。→ 洪兄统一口径组件。

## 5. 我们的差异化（市场空白定位）

洪兄的站点不与「模板建站」竞争，而与「真实、可玩、有学术脉络的个人作品集」竞争。三张差异牌：

1. **真实可玩**：外链已上线的网页游戏（如《抉择的房间》），访客点开即玩——多数竞品只有视频/截图，Pippin Barr 之外极少做到「每作可玩」。
2. **学术 + 创作双脉络**：澳门科技大学 人文艺术学院 互动媒体艺术·游戏设计背景，详情页呈现设计研究方法论（呼应 OceanEye 范式但更聚焦 Unity 互动叙事），同时统一《澳里·光景》=学位作品、《青峦·听雨》=可玩子项目的严谨口径。
3. **内容矩阵互通**：小黑盒 / 知乎文章 ↔ 作品集互链，形成 SEO 与引流闭环；真实画师授权图按小黑盒模式标注 `artist`/`source`，以「真实归因」对抗「AI 验证图」痛点。

## 6. 核心功能清单（RICE 排序）

评分维度：Reach(1–10) / Impact(0.25–3) / Confidence(50%–100%) / Effort(1–10 人日)。
`Score = (Reach × Impact × Confidence) / Effort`，分数越高优先级越高。

| 功能 | Reach | Impact | Confidence | Effort | Score | 优先级 | MVP? |
|------|-------|--------|------------|--------|-------|--------|------|
| 作品详情页（hash 路由 #work/<id>，含真实可玩外链 + 设计过程 + 角色贡献） | 10 | 3 | 100% | 4 | **7.5** | P0 | 是 |
| 首页 Hero（去占位提质后的真实首屏） | 10 | 3 | 100% | 2 | **15** | P0 | 是 |
| 精选作品网格（含统一口径关系标注） | 10 | 2 | 100% | 3 | **6.67** | P0 | 是 |
| 关于 About（真实简介 + 学术/创作脉络） | 8 | 1 | 100% | 1 | **8** | P0 | 是 |
| 联系 Contact（外链邮箱 / 小黑盒 / 知乎） | 9 | 0.5 | 100% | 1 | **4.5** | P0 | 是 |
| 图库 Gallery（真实画师授权图 + artist/source 标注） | 7 | 1 | 80% | 3 | **1.87** | P1 | 否 |
| 无障碍 a11y（键盘可达 / 对比度 / ARIA） | 7 | 0.5 | 80% | 2 | **1.4** | P1 | 否 |
| SEO 基础（meta / OG / sitemap / 结构化数据） | 6 | 0.5 | 80% | 2 | **1.2** | P1 | 否 |

> 说明：统一对外口径（学位作品 vs 子项目关系标注）作为「精选作品网格」与「作品详情页」的内置质量项计入 P0，不单列为人日估算外的独立功能。

### 6.1 功能明细（6 大区块）

1. **首页 Hero** — 真实姓名 + 一句定位（如「互动媒体艺术 · 游戏设计研究生，专注互动叙事」）+ 首屏即见 3 个精选作品预览；无全屏动画、无模板欢迎句。
2. **关于 About** — 真实简介：院校/方向/研究兴趣；学术脉络（互动叙事、Flow/Narratology 取向可写）；外链至小黑盒/知乎。
3. **精选作品网格** — 3–5 个强作品卡片（质量 > 数量）；每卡片含封面（中性占位 + artist/source 接口）、标题、一句定位、**关系标注**（《青峦·听雨》注明「《澳里·光景》可玩叙事子项目」）。
4. **作品详情页（hash 路由）** — `#work/aoli-guangjing`、`#work/qingluan-tingyu` 等；含：概述、角色贡献、设计过程（problem→goal→prototype→iteration→result）、真实可玩外链（外链图标）、图片区（中性占位 + 元数据接口）、相关文章外链。
5. **图库 Gallery** — P1；真实画师授权图网格，每张标注 `artist`/`source`（小黑盒模式）；中性占位兜底。
6. **联系 Contact** — 邮箱外链（mailto，rel=noopener）、小黑盒主页外链、知乎主页外链；每作品页与页脚均可见。

## 9. 验收标准（Given / When / Then）

- **G1** Given 访客打开首页，When 首屏渲染完成，Then 立即看到姓名+定位+至少 3 个作品预览，且无任何占位欢迎句、无紫粉渐变、无 emoji 图标。
- **G2** Given 访客点击作品卡片，When 触发 hash 路由 `#work/<id>`，Then 单页内无刷新展示对应详情（不新增 html、不引框架），URL 可复制分享、刷新后仍在原详情。
- **G3** Given 详情页含《青峦·听雨》，When 访客阅读，Then 明确看到「《澳里·光景》可玩叙事子项目」的关系标注。
- **G4** Given 图片资源尚未提供，When 页面渲染图片位，Then 显示中性占位且 DOM 含 `data-artist` / `data-source` 元数据接口（值为空或占位文本，非 AI 图）。
- **G5** Given 详情页含可玩作品，When 访客点击外链图标，Then 在新标签打开真实网页游戏（rel=noopener），不破坏当前单页状态。
- **G6** Given 在 iOS/Android 微信内置浏览器与 Chrome/Safari/Firefox 最新两版，When 打开站点，Then 网格与详情页布局正常、无横向溢出、可正常点击。
- **G7** Given 移除 gallery 的 COS 脚本后，When 构建并部署，Then 站点零外部脚本依赖（除可选分析 SDK），无控制台报错与外链失效。
- **G8** Given 全站文案，When 内容审阅，Then 不含 `Welcome to`/`Lorem ipsum`/`Sign up today` 等禁用词，且所有陈述为真实信息。

## 10. 边界条件

- **空状态**：图片未提供 → 中性占位 + 元数据接口；作品少于 3 个 → 网格自适应，不显示空卡片。
- **错误状态**：外链失效 → 详情页标注「外链暂不可用」而非崩溃；hash 路由非法 id → 回退首页并提示。
- **加载状态**：图片懒加载 + 渐显；首屏不依赖大图。
- **边界值**：作品数 0 / 1 / 上限（网格最多 5）；标题超长 → 截断 + 完整标题 tooltip。
- **并发 / 离线**：纯静态无并发问题；离线 → 已加载资源可看，外链不可用优雅降级。
- **权限拒绝**：无登录/后端，无权限场景；mailto 在移动端无邮件客户端时提供复制邮箱兜底。

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | LCP < 2.5s（静态托管，无后端）；图片懒加载 + WebP/AVIF；首屏不引大图与重动画 | P0 |
| 可用性 | GitHub Pages SLA；无单点后端；核心流程（首页→详情→外链）零依赖外部失效脚本 | P0 |

## 12. 数据埋点方案

纯静态站点用轻量客户端 SDK（Plausible / Umami / GA4 任选，或自建 `trackEvent()` 封装），事件命名 `{对象}_{动作}`。

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | `page_view` | 来源渠道（小黑盒/知乎/直接） |
| 激活 | `work_detail_open`（带 `work_id`） | 访客是否真正进入作品详情 |
| 转化 | `playable_link_click`（带 `work_id`） | 真实可玩外链点击 = 核心差异指标 |
| 互动 | `work_card_click`、`gallery_image_view`、`contact_click` | 作品/图库/联系互动 |
| 异常 | `error_occurred` | 前端错误（含 hash 路由非法回退） |

**实现要求**：事件附带 `work_id`/`source`/`timestamp`/`device`；不采集 IP、不存原始输入；隐私合规（GDPR/个保法）备案说明。

## 13. Out-of-Scope（不做清单）

- 不引后端 / 服务端逻辑
- 不引前端框架（Vue/React 等）；零构建纯静态
- 不做 CMS / 后台管理
- 不做博客 / 文章系统
- 不新增 html 文件（详情页仅用 hash 路由）
- 本轮不填充任何 AI 生成图（仅预留 artist/source 接口 + 中性占位）
- 不做电商 / 支付 / 评论系统
- 不做多语言国际化框架（仅预留接口）
- 不做暗色模式切换、不做服务端渲染

## 14. 图标与视觉规范约束（落实 P0 规则）

- **图标**：全部使用语义描述词（「外链图标」「箭头图标」「编辑图标」「下载图标」），由设计师在 SVG 图标库中落地；禁止 emoji 字符作功能图标。
- **主色**：深墨/中性灰背景 + 单一强调色（建议青绿 `#1f9e8f` 区间或琥珀 `#c9821f` 区间，待设计师定稿）；**禁止 purple→pink 渐变**。
- **文案**：所有陈述为真实中文；建立禁用词校验（见 G8）；标题与 About 开头须为作者本人的真实一句话，不得沿用模板默认句。
- **设计令牌**：由架构师建立 CSS 变量（间距/字号/圆角/色板），消除 magic numbers（对应现状问题 3）。
