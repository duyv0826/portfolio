# 洪兄个人作品集全站 — 产品需求文档（PRD）

> 作者：许清楚（产品经理）
> 版本：v1.0（Phase 1 调研产出）
> 日期：2026-10-09
> 项目定位：为澳门科技大学互动媒体艺术 · 游戏设计方向研究生「洪兄」打造的个人作品集全站
> 受众：中文国内受众（毕业设计展示、校园大使、求职三大目标）

---

## 一、产品定义（一句话 + 目标用户 + 核心问题）

**一句话描述**：一个面向中文国内受众、由站长自主掌控内容与管理后台的轻量个人作品集全站，集作品展示、博客输出、访客订阅与留言于一体，并针对游戏设计作品的素材版权标注与国内合规（ICP 备案、百度 SEO）做了原生支持。

**目标用户（核心）**：站长本人（洪兄，游戏设计研究生）——需要以专业、可控、合规的方式向毕业评审、校园合作方与招聘方持续展示作品与思考。

**核心问题**：现有作品集方案要么离岸且贵（Webflow/Framer）、要么内容不归自己（Behance/Notion 子域）、要么需要重度技术自建且无易用后台（Astro/Next 模板），且普遍不解决「中文受众 SEO + ICP 备案合规 + 游戏美术素材版权标注」这三件对国内游戏设计求职者至关重要的事。洪兄需要的是一个「自己拥有、易更新、合规、且能讲清每张图来源」的站点。

## 二、目标用户画像

### 画像 A：洪兄本人（站长 / 内容生产者）— 主要用户
- 身份：澳门科技大学互动媒体艺术硕士，游戏设计方向，应届求职阶段
- 技术水平：会用设计工具（Figma/Blender/Unity 等），非专业前端，能接受简单后台操作，但不会维护服务器
- 核心诉求：
  - 毕业设计需要一个像样的线上展示入口
  - 求职时一键分享作品集链接，给人「专业、有品味、可信」的第一印象
  - 校园大使活动能快速发布活动心得、收集意向同学的联系方式
  - 作品的素材来源、授权、署名能清晰标注，避免版权纠纷（游戏设计大量使用素材/AI/客户项目图）
- 痛点：不想被平台绑架，不想花几百块/月订阅海外 SaaS，也不想学 Next.js 自己部署

### 画像 B：招聘方 / 面试官（访客 / 评估者）— 次要用户
- 身份：游戏公司 HR、主美、校招面试官，或毕业设计评审老师
- 技术水平：普通上网用户，手机/电脑混合访问，耐心有限（3 秒内要判断「这人行不行」）
- 核心诉求：快速看懂「他是谁、做过什么、解决过什么问题」，能下载/收藏作品集，能留下联系方式
- 痛点：很多作品集加载慢、图片无说明、版权不清，难以判断真实能力

### 画像 C：校园合作方 / 潜在粉丝（访客 / 订阅者）— 次要用户
- 身份：校内社团、活动合作方、对游戏设计感兴趣的同龄人
- 核心诉求：关注洪兄的动态（博客/新作品），通过订阅或留言建立联系
- 痛点：缺乏持续触达渠道，错过更新

### 3.2 替代方案（2+）

| 替代方案 | 定位 | 可借鉴处 | 不足 |
|----------|------|----------|------|
| **墨刀 / 即时设计（Pixso）** | 国内拖拽原型/UI 工具，可绑域名 | 中文界面、上手快、国内访问快 | 偏原型而非真正 CMS；内容管理弱；SEO 一般；不是为内容站设计 |
| **凡科 / 上线了（SaaS 模板建站）** | 国内 SaaS 建站，备案/HTTPS 一站式 | 备案/证书平台托管省心；中文客服 | 源码封闭、URL 结构固定难做长尾 SEO；定制性低；年费且功能受限 |
| **Hugo 静态站** | 极速静态生成器 | 免费、极快、可托管于国内 Pages | 纯静态无后端/数据库；无后台编辑；订阅/留言需第三方；无认证 |

### 3.3 竞品差评提炼的关键洞察
- Webflow/Framer 的共同槽点：**定价不透明、离岸、对国内访问与备案不友好、客服差**。
- Notion/Behance 的共同槽点：**内容不归自己、品牌弱、SEO 不可控、无结构化版权标注**。
- 开源模板的槽点：**无易用后台、技术门槛、部署合规自己扛**。
- → 市场空白指向：一个「**国内合规就绪 + 中文 SEO 友好 + 自托管数据可控 + 有易用 CMS 后台 + 原生支持游戏美术素材版权标注**」的轻量方案，目前没有人把这几件事打包做好。

## 四、我们的差异化（为什么选我们而不是竞品）

1. **数据自持 + 易用后台**：相比 Behance/Notion 子域与离岸 SaaS，本站后端 API + 数据库 + 管理员登录，内容、订阅、留言全部自己掌控，且有真正增删改查后台，非技术站长也能更新。
2. **国内合规与 SEO 原生就绪**：相比海外 SaaS（备案难、百度收录差）与纯静态模板（需自己搞），本站规划内置 ICP 备案号页脚位、sitemap、结构化数据、百度收录友好结构，部署目标为国内可访问节点。
3. **游戏美术素材版权标注（垂直空白）**：竞品普遍只给「图片+描述」字段。本站为每件作品提供结构化的「素材来源 / 授权类型（CC0/CC-BY/商用授权/原创/AI 辅助）/ 署名 / 客户项目授权状态」字段，并支持全站版权与「禁止 AI 训练」声明页脚——直接解决游戏设计求职者最容易被质疑的版权问题。
4. **零订阅成本 + 中文界面**：相比 Webflow/Framer 长期月费，本站一次性自建、无月费；界面与文案全中文，贴合国内受众。

## 六、MVP 范围

**纳入 MVP（按主理人定义）**：
1. 展示前台：首页、作品列表与详情、博客列表与详情、关于页、订阅与留言表单
2. CMS 后台：作品与博客文章的增删改查（需管理员登录）
3. 访客订阅与留言：数据写入数据库，后台可查看

**明确不做（Out-of-Scope，每条带原因）**：
1. **用户注册/多角色权限系统** — 原因：MVP 仅需单个管理员，多用户体系增加认证与授权复杂度，超出「管理员登录」最小需求。
2. **在线支付 / 电商 / 打赏** — 原因：个人作品集非经营性质，且个人备案禁止电商/交易类内容，合规不允许。
3. **评论区公开互动（访客互评）** — 原因：MVP 用「留言表单 + 后台查看」即可，公开评论需审核/防 spam 体系，留待后续。
4. **国际化 / 多语言（i18n）** — 原因：受众明确为中文国内，英文版无即时需求，预留接口即可不实现。
5. **AI 辅助写作 / 自动生成内容** — 原因：内容为站长原创，AI 生成反而是版权风险点，不在 MVP。
6. **作品集模板市场 / 多租户** — 原因：仅服务单一站长，不做 SaaS 化。
7. **实时通知 / 邮件自动回复** — 原因：MVP 仅落库 + 后台查看，邮件推送、短信通知等留待增强。
8. **复杂数据分析看板** — 原因：先做核心埋点（见第十节），看板可视化后续迭代。

## 七、关键验收要点（Given / When / Then）

**前台**
- Given 访客打开首页，When 页面加载完成，Then 3 秒内展示首屏（站长介绍 + 精选作品 + 行动号召），且首屏文字为中文、无占位文案。
- Given 访客进入作品列表，When 点击某作品卡片，Then 跳转作品详情页并展示封面、图集、描述、标签与（若已填）素材来源/授权信息。
- Given 访客进入博客列表，When 点击文章，Then 进入详情页渲染 Markdown 正文与发布时间。
- Given 访客在关于页，When 浏览，Then 看到站长故事、技能与联系方式（邮箱/社交链接）。
- Given 访客在订阅表单输入合法邮箱并提交，When 后端校验通过，Then 写入订阅表并返回成功提示，邮箱格式非法时给出明确错误。
- Given 访客在留言表单填写姓名+内容并提交，When 校验通过，Then 写入留言表并返回成功提示。

**后台**
- Given 未登录用户访问 /admin，When 尝试进入，Then 被重定向到登录页。
- Given 管理员用正确账号密码登录，When 登录成功，Then 进入后台仪表盘。
- Given 管理员在后台创建/编辑/删除作品，When 提交，Then 数据库对应记录变更且前台列表/详情同步更新。
- Given 管理员在后台创建/编辑/发布/删除博客文章，When 提交，Then 前台博客列表与详情按状态（草稿/已发布）正确呈现。
- Given 管理员查看订阅与留言列表，When 打开对应页面，Then 看到全部记录及提交时间，并支持删除。

**通用**
- Given 任意页面，When 在移动端（375px 宽）访问，Then 布局不破版、可正常操作（响应式基线）。
- Given 任意表单提交，When 触发，Then 输入经后端校验、含速率限制，防止 spam 与注入。

## 八、边界条件

- **空状态**：作品/博客为空时，列表页展示引导文案（如「暂无作品，敬请期待」），而非空白或报错；后台空列表给出「去新增」入口。
- **错误状态**：表单校验失败、网络异常、数据库写入失败均需友好中文提示，不暴露堆栈。
- **加载状态**：列表/详情加载使用骨架屏或加载指示，避免白屏。
- **边界值**：邮箱长度、留言字数、上传图片大小（建议单图 ≤ 5MB，与行业共识一致）需设上限并提示。
- **并发**：同一管理员多端登录、高频提交需有基础防护（速率限制）。
- **离线**：无网络时表单提交给出明确失败提示，不静默丢失。
- **权限拒绝**：非管理员访问受保护接口返回 401/403 并跳转登录。

## 十、数据埋点方案（PRD 必含）

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | `page_view`、`sign_up_complete`（订阅成功计为转化） | 新访客来源、订阅转化率 |
| 激活 | `first_work_view`（首次查看作品详情）、`first_blog_view` | 访客是否触达核心内容 |
| 留存 | `session_start`、`session_duration` | DAU/MAU、访问频次 |
| 转化 | `subscribe_click`、`subscribe_complete`、`message_submit` | 订阅与留言漏斗 |
| 异常 | `error_occurred` | 前端错误 + API 错误 |

**实现要求**：前端用轻量 SDK（如 Umami / 自建 `trackEvent()` 封装）；事件命名 `{对象}_{动作}`（如 `work_viewed`、`subscription_completed`）；属性含 `user_id`（匿名访客用会话 ID）、`timestamp`、`device`、`version`；不采集隐私数据（不上报 IP、不存留言原文到分析系统）。

## 十一、数据模型建议（供架构师参考，非技术决策）

- **works（作品）**：id、slug、title、cover_url、gallery（图集 JSON）、description（Markdown）、role、year、category、tags、material_source、license_type、attribution、client_auth_status、created_at、updated_at
- **posts（博客）**：id、slug、title、cover_url、excerpt、content（Markdown）、tags、status（draft/published）、published_at、created_at、updated_at
- **subscribers（订阅）**：id、email、created_at
- **messages（留言）**：id、name、email、content、created_at
- **admins（管理员）**：id、username、password_hash、created_at

## 十三、RoleVerdict（核心结论，结构化回传）

**verdict（结论）**：
强烈建议按主理人定义的 MVP（展示前台 + CMS 后台 + 订阅留言）推进开发。该范围边界清晰、技术路径标准（前端 + 后端 API + 数据库 + 管理员认证），可在可控工期内交付一个「数据自持、国内合规、中文界面」的作品集站，显著区别于离岸 SaaS 与平台型方案。并强烈建议将「作品素材版权结构化字段」纳入首版，作为面向游戏设计求职者的核心差异化。

**blocking（阻塞项）**：
1. **部署节点与备案归属待主理人确认**：国内合规要求域名解析至大陆服务器并完成 ICP 备案（个人备案禁电商/社区）。需明确由谁提供域名与服务器、备案主体（洪兄本人），否则上线合规链路无法闭环。
2. **MVP 是否纳入「版权结构化字段」需主理人拍板**：该字段成本低（RICE 4.27）且高度贴合游戏设计身份，但会改变作品数据模型与后台表单，须在开发前定。

**advisory（建议）**：
- 视觉上采用「深青/墨绿或蓝系品牌色 + 暖白背景」，规避紫粉渐变；图标用 SVG 图标库、文字描述，不用 emoji。
- 默认满足响应式与基础 SEO（sitemap/结构化数据），即便不单独排期。
- 订阅/留言先做落库 + 后台查看，邮件通知等增强后置。
- 界面与所有样例文案使用真实中文内容，避免占位文本。

**evidence（依据）**：
- 竞品定价与差评：Webflow $14–235+/月且账单混乱（ToolRadar/Capterra 差评）；Framer Trustpilot 1.8/5、升级后 CMS 集合反降、1GB 带宽与 5MB 上传限制（freebestwebsitebuilders 评测）；Notion/Behance 内容不归己、子域品牌弱。
- 国内合规：域名解析至大陆服务器必须 ICP 备案，未备案将被阻断访问（阿里云备案、工信部法规、CSDN 2026 指南）。
- 创意版权：游戏/美术作品集需结构化标注素材来源与授权，并加「禁止 AI 训练」声明（喵闪网版权声明指南、Blended Boris AI 防护、Cinevva 游戏素材许可证）。
- 开源模板优势与短板：Astro/Next 性能佳但无易用后台、需自建部署（StarterPick、AdminLTE 2026 模板综述）。
